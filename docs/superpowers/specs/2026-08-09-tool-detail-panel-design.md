# 工具详情浮层：会话探索器 + 上下文趋势 — Design Spec

> 日期：2026-08-09
> 状态：草稿（待审阅）

## 问题概述

现有 Claude Code / ChatGPT 详情面板只回答了“钱花在哪”（模型、缓存拆解），没有回答核心问题：**花了多少、值不值、感受到消费、看到了什么结果**。同时，展开卡嵌在仪表盘内，可用空间有限。

本次设计把信息拆成两层：

- **仪表盘结论卡**：回答时间段维度的总结（花了多少 / 得到什么 / 值不值），只保留 3 行；
- **浮层**：整面覆盖仪表盘窗口的会话探索器，回答会话维度的明细——特别是每个会话里**上下文窗口随轮次的增长趋势**（越接近上限，越该压缩）。

## 设计目标

1. 结论卡三行数字与仪表盘总览口径一致（同一批 SQL、同一批会话）。
2. 浮层以会话为单位展示数据，让每笔花费挂到具体的事（标题、仓库、金额）。
3. 会话内展示逐轮上下文增长，把“该压缩了”变成可见、可行动的信号。
4. 浮层覆盖整个仪表盘窗口后可滚动；被覆盖区域不再有自己的滚动，不存在双滚动混淆。

## 明确不做

- 不做对话内容浏览 / AI 主题分析 / 游戏化。
- 不加 tab、不加新独立窗口。
- 不重复仪表盘已有的图表（成本柱、模型 donut 等）。
- 浮层不做时间段费用汇总（那是结论卡的职责），顶部只保留一行极简摘要。

## 交互与形态

1. 点击仪表盘工具行（Claude Code / ChatGPT）→ 展开结论卡（3 行）。
2. 点击结论卡 → **浮层整面覆盖仪表盘窗口**（窗口内 ZStack 覆盖，非新窗口、非 popover）。
3. 浮层可滚动，高度 = 窗口高度；带 “✕” 关闭，Esc 也可关闭。
4. 浮层顶部摘要行：工具名 · 时间范围 · N 个会话 · ¥X（仅作上下文，不重复结论卡）。

## 仪表盘结论卡（3 行）

1. **花了多少**：本期 ¥X · 较上期 ↑/↓Y% · 本月预计 ¥Z
2. **得到什么**：N 个会话 · M 次提交 · +K 行代码
3. **值不值**：每次会话 ¥A（较上期 ↓10%）· 每千行 ¥B · 与另一工具对比（如“ChatGPT 比 Claude Code 贵 18%”）

行尾显示小箭头图标，提示可点击查看详情。

## 浮层主体：会话列表

### 筛选口径

- 列表只显示**该时间范围内存在交互的会话**（与结论卡数字同批）。
- 例外：展开后的上下文图表显示**该会话的完整轨迹**（所有轮次），不受时间范围截断。列表筛选按范围、图表按整会话，两个口径分开。

### 按仓库分组

- 过滤后的会话按仓库分组；组名 = `repo_path` 最后一段（与仪表盘仓库列表口径一致）。
- 无仓库的会话单独归入“（无仓库）”组。
- 组按**总花费降序**排列；组头显示：项目名 · N 个会话 · ¥X。
- 组头可折叠（30 天会话多时有用）。
- 会话归属仓库 = 该会话首个事件的 `repo_path`。

### 组内排序

- 默认按时间倒序；分段控件可切换“最近 / 最贵”。
- 每行：时间 · 标题（首条用户消息，截断 60 字符）· 金额 · 右侧上下文占用小条（窗口已知时）。

### 行内展开

- 点击会话行 → 在行下方内联展开图表区；同一时刻只保持一个展开态，点击其他行切换。
- 展开区包含：逐轮上下文趋势图 + 会话指标。

## 会话详情（行内展开的图表）

### 逐轮上下文趋势图

- X 轴：轮次序号；Y 轴：输入 token。
- 实线 = 每轮输入；浅色面积 = 缓存部分；虚线 = 窗口上限（已知时）。
- 输入突降处标注“已压缩/重开”。
- 突降判定：下一轮输入 < 前一轮输入 × 0.7（阈值后续可调）。

### 指标行

总轮次 · 最终占用 % · 总费用 · 缓存节省金额。

### 行动提示

最终占用 > 80% 时显示：“该会话接近上下文上限，建议压缩/新开会话”。

## 数据层

### 新表 `session_info`

| 字段 | 说明 |
|---|---|
| `source` | 工具来源（claude-code / codex） |
| `session_id` | 会话 ID |
| `title` | 首条用户消息，截断 60 字符 |
| `repo` | 会话首个事件的 repo_path |
| `first_ts` / `last_ts` | 会话起止时间 |
| `completed` | ChatGPT：来自 task_started/task_complete；Claude：NULL |
| `window_tokens` | ChatGPT：model_context_window；Claude：模型常量，未知则 NULL（图表省略虚线） |

写入时机：LogWatcher 增量解析时顺手写入/更新。

### 逐轮序列

复用 `usage_event`（`ts`、`in_tokens`、`cache_tokens` 按 `(source, session_id)` + `ts` 排序），无需新增日志解析。

### 新增查询（StatsService）

1. 结论卡：per-tool 花费 + 环比 + 月度预测；会话数 / 提交数 / 行数；每次会话成本（总花费 ÷ 会话数）；CPL；跨工具对比。
2. 会话列表：范围内会话按仓库分组，含各组数量与成本。
3. 单会话序列：`usage_event` 按 ts 排序 + `session_info.window_tokens`。

### 产出归属

沿用现有模型：会话所在 repo 的 `code_change`（提交、行数）归该工具，与现有 CPL 口径一致；文档注明为近似归属。

## 文案与本地化

新增 I18n 键并覆盖全部 10 种语言：面板标题、分组标题（含“（无仓库）”）、排序切换、占用提示、压缩标注等。

## 测试与验收

- 结论卡三行数字与仪表盘总览一致（同一批 SQL）。
- 浮层打开 <100ms（查询可缓存）。
- 列表筛选 = 范围内有交互的会话；展开图 = 完整会话轨迹。
- 测试覆盖：`session_info` 捕获、新统计 SQL、仓库分组、压缩点检测、80% 阈值提示。
