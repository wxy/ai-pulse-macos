# 事实优先的统一脉搏

2026-09-17 · 独立分支 `codex/fact-first-unified-pulse`；本轮是 PR #69 收口之后的新改造，既有人工验收不自动覆盖新视觉。

## 第一性原则与体验取舍

用户需要知道投入正在发生、已经积累多少、有什么伴随成果。我们没有完整账单，也不知道每个词元的实际付款成本；因此不能把活动强度称为金额、收费速度、预算百分比或价值判断。

- 当前脉搏只由已观察的词元活动驱动。余额下降、额度使用及本地 Git 成果独立显示，不抢占当前等级，也不把提交当作消费。
- 强度档位是有规则的感知指标，不是直接事实。准确的近期／今日观察总量用于解释它，始终限定支持日志的覆盖。
- 不计算趋势斜率，就不称“加速”；历史不足，就不称“平时”。大量活动停止后要回落，并明确显示余波。
- 两个出口共用一次当前状态发布、同一配色及同一个消费跳动时钟，不让用户学习两套图例。
- 不持续闪烁、缩放应用图标或反复响声。减少动态效果时保留静态状态和事实说明，不播放视觉跳动。

## 计算规则

近七天支持日志按统一 TokenAccounting 规则归一，排除未来与合成活动；强度计算使用五分钟聚合样本，以该桶末条活动时间作衰减近似。它不是逐词元精确计量。

当前窗口一小时，十分钟半衰期。加权值换成平滑小时参考指数时，除以指数核的有效时长，再乘 3600；恒定流量不会被原来任意的乘六系数额外放大。该指数不是实测每小时用量。

个人参考是近七天历史活跃小时的中位数，至少覆盖八个活跃小时、三个 UTC 日；与最近一小时重叠的整小时不进入参考。条件不足使用固定 20K 词元／小时参考，文案明确历史不足，不称个人平时习惯。

以指数／参考形成等级分数；任何近期有效词元活动有随时间衰减的微弱可见底线。分数上限为 `8 × 0.5^(距末次活动秒数 / 600)`，避免巨大旧批次长期卡在最大等级。个人比较文案使用未截断的指数／历史参考，不把视觉限幅冒充真实倍率。

| 分数 | 状态文案 | 火焰／状态灯颜色 |
| --- | --- | --- |
| < 0.15 | 暂无近期活动 | 灰；Dock 不点亮活动灯 |
| 0.15～< 1.5 | 正在投入 | 金 |
| 1.5～< 3 | 投入较高 | 橙 |
| ≥ 3 | 高强度投入 | 暖红 |

末次活动超过十分钟且仍有余波时，状态文案改为“投入回落中”，颜色随剩余强度下降。一小时外不再驱动当前活动。未知与有效平静均用中性灰，但必须以“观察不可用”与“暂无近期活动”文字区分，不能靠颜色宣称健康。Dock 在两者下保留默认机器人，不制造活动灯。

近期十分钟与今日总量直接查询原始观察，不使用衰减、固定参考或倍率；近期窗可跨午夜，今日从本地日历零点开始，两者截止于同一次观察时刻。分项缺失明确说明；查询失败不造零，失效缓存不冒充当前状态。今日提交来自授权 Git 根独立事实，缺失显示不可用，不暗示 AI 创作。

## 展示与反馈

菜单栏恢复十八点火焰＋状态文字；Dock 保留机器人原图，只在图标内下方固定留白处点亮活动状态灯，采集健康角标保持独立。删除外围分节圈及旧预算圈／圈数／整图缩放代码。两者共用灰／金／橙／暖红配色与状态来源，不要求使用相同外形；仪表盘状态点也共用配色。

消费跳动仅订阅既有 `consumptionDidOccur`：支持日志新近期活动或可观察的余额消费事件；普通刷新、历史回读、Git 扫描、额度升高及启动不制造跳动。余额事件依然是区间净下降观察，不是逐笔付款证明。共用两秒合并门槛及 320 毫秒短亮，火焰与状态灯同时提高亮度，灯短暂增加柔光，不缩放机器人图形。无词元活动时，新余额观察可用金色短亮，但不改变或伪造词元等级。现有声音静音、时段及限次规则不变，不声称声画逐帧精确同步。

展开菜单显示最近十分钟词元、今日词元与本地提交，金额和各额度窗口另列；没有金额观察不估算，额度过期／读取失败与成功为空分开。等级解释及图例放在悬停提示中，避免主标题变成技术参数墙。新状态、事实与图例覆盖十种应用语言；SwiftPM 测试读模块本地化资源，Xcode 应用读主 bundle。
