## 1. 用户确认的设计约束

### 消费感与事实边界

观察事实、声明上下文、感知指标各自保持独立。词元不是付款金额；活动等级不是账单、预算百分比、价值评价或服务商真实成本。

- 月费不加入今日 API 金额、不按日摊销、不要求用户填账期起点／周期。只在 30 天视图提供已登记固定投入背景，不声称当月已经实际支付。
- 账户金额观察来自余额采样区间净下降，可能包含充值、退款等因素，不冒充逐笔消费。没有有效观察时隐藏整个金额块。
- 不统计远程 PR／GitHub Release；本地 Git 增加行、删除行、提交数是成果信号，不能证明 AI 创作归属。
- 只关联配置开发目录内的 Git 仓库；工作区路径、日志 cwd 不自动等于仓库路径，无效路径不能变成虚构仓库。
- 三个周期各保留独立快照，切换选择快照，不把一份数据复写成另一周期。请求代次阻止旧异步结果覆盖新结果。
- 应用语言采用现有地区规则：中文界面视同中国区，配置 OpenAI 切换英文；不为开发版新增绕过开关。账户服务商与本地开发工具卡片不是同一层，不能混为一谈。
- CloudKit 2.x 尚未正式发布，无须保留此前未发布的 2.x 兼容链；现行数据版本可以保持 2.0。旧原始历史不因清理旧计费逻辑而删除。正式环境部署不在已完成事项内。

### 本地化与单位

中文统一使用“词元”，不是 Token／词源／次元。数量支持 K、M、G、T，缩写与需要的小数保留一位。实际零与读取失败不同：失败显示不可用／“—”，不造零。

## 3. 当前实现：统一脉搏

完整规则以 [事实优先的统一脉搏](fact-first-unified-pulse.md) 和当前源码为准。

- 强度只由已观察词元驱动；余额、额度、本地 Git 成果独立列出。
- 当前窗口一小时、十分钟半衰期；五分钟桶近似衰减，用有效核时长归一，得到平滑小时参考指数，不称实测每小时用量。
- 个人参考为近七天历史活跃小时中位数，至少八个活跃小时、三个 UTC 日，排除与最近一小时重叠的整小时；不足时用 20K 词元／小时固定参考并明确历史不足。
- 分数小于 0.15 为暂无近期活动；0.15～不足 1.5 为正在投入；1.5～不足 3 为投入较高；3 及以上为高强度投入。视觉分数有随末次活动时间衰减的上限，避免旧巨量批次长期卡在最高档。
- 灰／金／橙／暖红共用一套颜色；余波显示投入回落中。观察不可用与有效平静必须由文字区分。
- 菜单栏保留火焰与文字；Dock 保留原机器人，只点亮活动灯，健康角标独立。已删除外围分节圈、预算圈与整图缩放，不追求两个出口同形。
- 共用消费事件跳动时钟：两秒合并门槛、320 毫秒短亮。历史回读、普通刷新、Git 扫描不制造消费跳动；减少动态效果时保持静态。余额新观察可短亮，但不伪造词元等级。
- 最近十分钟／今日词元是直接观察事实，不使用衰减倍率。声音继续遵守静音、时段和限次，不声称声画逐帧同步。

## 4. 当前实现：机器人与数据表

### 头像

- 周期切换居中置于头像内顶部，不再重复窗口的仪表盘标题；天线附着头像并一起滚动。
- 额头第一行放扫描／警告／活动状态，固定高度；词元总数下方依次是会话与活跃日、完整周期均速。均速分母为今日 24 小时、本周 7 日、30 天 30 日。
- 左眼为工具用量（词元）；右眼为仓库变化（行数），即增加＋删除等权，不是净增。圈图中心保留单位。
- 鼻子为上小下大梯形，上删下增，以高度比例表示数量；上下外缘圆角、红绿内部分界保持直连。增删标签在图外，鼻子相对眼睛下移；提交数在下方独立留白，不显示净增减。
- 嘴部两条节奏各自归一化：词元朝下、代码朝上，留间隔不重叠。无数据仍是分节灰色基线，不是一条连续直线。
- 今日按真实事件时间进 24 小时槽位；30 天为 30 日；本周有中间 7 个真实日及两侧各 7 个视觉占位，总计 21 槽。两侧只有无数据灰线，没有虚线或“上周／本周／下周”标签，不读取相邻周、不参与统计或峰值。

### 表格与详情

- 工具×模型和按仓库表使用单元格半透明数据条；按相关数值列明细最大值缩放，合计不参与缩放。
- 工具×模型保留完整列；小矩阵铺满可用内宽，多列保留最小宽度并允许横向滚动。模型按总量排序，默认最多五行，可展开；合计始终来自完整数据并保持可见。
- 工具列标题左对齐，模型数字与合计数字的表头／数值右对齐；工具名附明显进入图标。重复详情下拉入口已删除。
- 详情是同窗口返回导航，不使用独立关闭叉。隐藏主仪表盘而不销毁，保留三份快照与滚动状态。
- 全零的未知模型分组隐藏；仍有有效活动的未知模型保留，不能为了美观伪造模型身份。
- 仓库默认五行，折叠时完整合计始终显示；增加／删除行使用 KMGT。增加与删除共享数值尺度，词元与提交分别取各自最大值；展开不改变尺度。
- 某仓库词元不可用时，词元合计不可用而不是把缺失当零；行数和提交非负饱和求和，防止整数溢出。代码读取失败单独显示不可用。

### 备注提示

词元分项缺失、余额净下降采样说明移到相关位置的叹号。按钮使用手形光标，悬停即展示独立浮层，点击固定，离开约 200 毫秒后收起以允许移入内容。旧的大数字整体悬停提示已删除。真正读取／采集失败仍应醒目显示，不能藏成普通备注。

## 5. 声音、通知与素材边界

- 通知设置与通用平级，系统通知和声音设置分组；一键静音与静音时段放一起。关闭时段后起止时间不可编辑，关闭消费音后每小时限次不可编辑。
- 声音包选择独立；单次、连续消费以及提示钟声各自的开关与试听对应明确。日中收盘／启动使用提示钟声；用户已确认素材与听感，不再主动试听。
- 三套为金币、水滴、收银机，各有 coin／coins／chime 三个槽位。九份 MP3 仅本地保留并打包，不上传 GitHub；仓库只保留 `Resources/Sounds/README.md` 等来源说明。
- 来源是用户提供的 Pixabay 链接。不要笼统写成 CC0，也不要声称九份均已确认 FreeSound CC0；具体授权结论按来源说明及实际许可核对。剪静音／去元数据不自动解除许可义务。
- 一键静音、时段、次数与成功播放计数已有策略回归；旧人工确认不扩展为本轮新增视觉的运行证明。

## 7. 当前启动故障：已定位，恢复未验证

### 现场事实

用户 2026-09-18 14:23 的 Xcode Debug 进程没有进入应用主逻辑。五秒现场采样只有主线程，停在 `dyld4::prepare → dyld4::halt → abort_with_payload`。容器 `diagnostics/events-active.jsonl` 的最后正常记录属于此前实例；新实例无 `app_launch`。

系统内核明确报 `Library Validation failed … mapping process and mapped file … have different Team IDs`。主程序／debug dylib 为正常开发团队签名，嵌入的 `Contents/Frameworks/libgit2.1.9.dylib` 是 ad hoc、没有 Team ID。库时间对应助手此前未签名构建，主程序随后由用户增量构建重签。

项目 Embed Libraries 已设置 `CodeSignOnCopy`，不是已经证明项目漏配签名。现场说明本次卡在加载器，不是已经证明本轮表格有 SwiftUI 死锁，也不能据此排除其他尚未验收的 UI 问题。

### 原因与责任

助手用同一 workspace、同一默认 DerivedData 执行 `CODE_SIGNING_ALLOWED=NO`，覆盖了用户 Xcode 使用的应用包；后续增量构建未重新签嵌入库，触发 Library Validation。问题在验证隔离方式，不能靠关闭系统校验掩盖。

### 恢复顺序

1. 在 Xcode 停止当前调试进程。
2. Product → Clean Build Folder（⇧⌘K）。
3. 保持正常签名设置，用 ⌘R 重新构建运行。
4. 如仍失败，重新采集当前进程、签名与加载器日志，不套用本次结论。

本会话只完成诊断与给出恢复步骤，没有代用户停止、重签、删除构建目录或重新启动；恢复尚未验证。`e37185c` 和本文都不包含启动修复。

以后助手未签名检查必须显式使用独立 `-derivedDataPath`，不触碰用户正在调试的产物。不得通过禁用 Library Validation、关闭签名或添加宽松 entitlement 来让错误签名产物启动。
