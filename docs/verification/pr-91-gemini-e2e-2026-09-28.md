# PR #91 Gemini CLI session verification (2026-09-28)

## Reproduce

Run from the repository root on macOS arm64 with Xcode's Swift toolchain, resolved SwiftPM dependencies and the repository's bundled native libraries. This host requires `--disable-sandbox` because SwiftPM's nested `sandbox-exec` cannot initialize. Module caches and build scratch stay in `/private/tmp` and may be deleted after the run.

```sh
mkdir -p artifacts/pr91-gemini-session-e2e
CLANG_MODULE_CACHE_PATH=/private/tmp/aipulse-gemini-clang-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/private/tmp/aipulse-gemini-swiftpm-cache \
XDG_CACHE_HOME=/private/tmp/aipulse-gemini-xdg-cache \
swift test --disable-sandbox --scratch-path /private/tmp/aipulse-gemini-build \
  --filter GeminiCLIParserTests \
  > artifacts/pr91-gemini-session-e2e/swift-test.log 2>&1
```

The reproducible inputs are generated by `Tests/GeminiCLIParserTests.swift`: synthetic parent and nested subagent JSONL logs, malformed headers, appended messages, and fresh SQLite databases. One database contains a pre-fix `gemini-cli` event with a NULL `session_id` and a saved checkpoint at EOF; another contains a permanent orphan NULL row while an unrelated session file grows through three appends. The tests run the JSONL checkpoint reader, Gemini parser and production SQLite event writer or session-ID repair. They reload repair state from SQLite to simulate a process restart, then change a file, introduce a new file, and temporarily remove a file. Temporary JSONL files are removed after each test; no user Gemini logs or database are read.

## Observed result

The command exited 0 on 2026-09-28: 9 `GeminiCLIParserTests` passed, 0 failed. The local log is `artifacts/pr91-gemini-session-e2e/swift-test.log` (gitignored); rerunning the command regenerates it.

Checks cover header session identity on initial and resumed scans, distinct nested subagent identity, replay deduplication, skipping records without tokens, rejection of malformed headers, and the EOF-checkpoint repair. Repair state is stored in the same SQLite database. An unchanged file is skipped after restart; a file that only grows and retains its inode, creation time, header signature, and prior 4 KiB boundary signature resumes from the saved complete-line cursor. The orphan-row test checks that each of three appends starts at the previous file size. Same-size rewrites, truncation, rotation, header changes and newly found files start from byte zero; unavailable or invalid files are not marked complete. The repair streams JSONL outside the database write lock and updates at most 512 keys per transaction. It updates only a matching `gemini-cli` row's NULL `session_id`; its token counters and checkpoint remain unchanged, and another source is untouched.

The test uses synthetic files and a fresh database. It does not launch the app or inspect a real Gemini CLI installation. A historical NULL row can be repaired only while its corresponding JSONL file and valid header are still available; deleted or malformed logs remain unattributed. If a file changes during its repair, completed batches may already have updated matching IDs; no completion marker is saved and the next scan retries idempotently. The bounded boundary signature detects rewrites near the cursor but cannot prove that every byte earlier in a large file stayed unchanged when the file also grows; exact proof would require rereading the old prefix and recreate the repeated-scan cost.
